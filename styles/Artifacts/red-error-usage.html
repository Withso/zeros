Red / error — how each case looks

Every red/error UI case rendered on the app canvas: Today (current --destructive, oklch) vs Proposed (red palette, borders dropped). Faithful to the real markup — icons, mono text, the neutral-text fail row, the green sibling badge, etc.

Rule

On a --red-bg surface, text + icons use --red-fg (softer salmon) — never the vivid --red-primary. Vivid red is only for standalone accents (−N counts, icons, borders); solid delete = --red-secondary. The Proposed column below applies this.

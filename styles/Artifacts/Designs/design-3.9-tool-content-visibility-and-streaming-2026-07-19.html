§3.9 Tool-content visibility & streaming · Design catalog · 2026-07-19

If the agent saw it, you see it — while it happens, not after

§3.9 decides whether the transcript is a live window into the agent's work or a report that arrives late: screenshots a tool returned, the log of a long command, each distinct piece of reasoning, a token bill that ticks while you watch. Fourteen rows, re-audited against the live code on 2026-07-19: one shipped since the doc (Codex willRetry — now a quiet retry chip), the Claude image bug turns out to be translator-only (the renderer already draws images), and the Cursor delta channel remains the keystone blocking three rows. Eight cases get a before / after below; the invisible-wiring rows are tabled with exactly what to implement.

Live window, not late report Nothing a tool produced is invisible, output grows while the command runs, and the app is honest about retries, failures and cost — in the moment.

Nothing the agent produced is invisible

A screenshot a tool returned renders as an image, not a JSON blob. Every reasoning part shows as its own thought. A truncated output says so. The renderer is already able to draw all of it — the translators just have to stop dropping it.

Streaming means live, not at the end

A two-minute command shows its log growing, not a flickering last fragment or a wall of text at completion. Text arrives token-by-token; the token/cost counter ticks during the turn, not once it settles.

Quiet when it self-heals, honest when it fails

A transient error the agent retries itself is a quiet "reconnecting" chip — never a red bubble above a successful reply (shipped). A terminal systemError settles the turn at once — the composer never sits locked for ten minutes.

The Cursor delta channel — one host event unlocks live text, live shell, and a real bill

The groundwork has started: an onDelta probe already sits in the host logging turn-ended usage to stderr, with a comment planning the real run.usage forwarding (cursor-host.cjs:204-224).

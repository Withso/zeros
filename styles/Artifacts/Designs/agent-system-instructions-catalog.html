The verbatim wire texts Zeros injects into Claude / Codex / Cursor sessions: the one-shot first-turn orientation, the Create-PR brief, the PR-island action prompts, the Review-tab composer briefs, and the background/synthesized messages — plus the delivery mechanics, the config knobs that ride alongside, and an audit of gaps and edge cases. One editable home

Every hardcoded string Zeros injects into an agent prompt lives in packages/protocol/src/system-instructions/templates.ts, tagged [SYS-INSTR: <id>]. PR-action prompts live in apps/desktop/src/renderer/shell/pr/pr-instructions.ts + pr-action-prompts.ts. Nothing else in the codebase is allowed to hardcode agent-facing prose.

Wire text ≠ bubble text

Auto-sent actions show the user a tidy label ("Create a PR", "Resolve") on the brown "sent by Zeros" bubble while the agent receives the full brief. The split rides sendPrompt(text, displayText, …, autoAction); the bubble is copy-only.

Two delivery mechanisms

A — in-band (Claude, Cursor): the body is wrapped in <system_instruction>…</system_instruction> and prepended to the first user message. B — native channel (Codex): the same body, unwrapped, on thread/start|resume.developerInstructions — it survives compaction and never masquerades as user speech.

Part A — Session start · the one-shot first-turn orientation

A1 Shipped Every new chat · once

The workspace preamble — [SYS-INSTR: workspace-preamble]

The base, agent-agnostic orientation. Injected once, on the first user message of every new chat (Claude / Codex / Cursor alike), then it lives in the conversation history — it is not re-sent per turn. Deliberately minimal: only what the agent cannot infer — where to work, what to diff/PR against, and that the branch isn't its to rename.

Part B — Create PR · the shared Changes / Review status row

B1 Shipped No agent message

"Create PR directly" / "Create draft directly" — explicit engine path

These explicitly labelled dropdown shortcuts do not talk to the agent. They call the engine's authenticated gh.prCreate with a small deterministic draft built from branch commits: title = the oldest branch commit's subject (usually the feature intent), bounded to 80 chars (…slice(0,77) + "..."), falling back to the humanized branch leaf; body = ## Summary + one bullet per commit subject (never empty — the engine rejects empty bodies). Dirty tree → committed (2026-08-01): a pull request can only carry committed work, so the button sweeps the worktree (git add -- . ':(exclude).zeros') and writes the commit itself rather than handing the chore back. No model call — the message is generated.

B2 Shipped Auto-sent prompt

Primary "Create PR" / "Create draft PR" — the full agent brief

The main segment, the draft menu item, and the dirty-tree recovery all send this brief to the active agent. Generated from live workspace state — branch, target, configured remote, uncommitted count (net HEAD-vs-worktree), upstream presence, and configured GitHub repository — then the agent verifies those facts before it writes anything. Parked while the agent has a turn in flight (the brief would describe a half-done tree). The chat bubble shows only "Create a PR" / "Create a draft PR" with the button's icon; the agent receives everything below.

- Commit them. Follow any instructions the user gave you about writing commit messages.

B3 Routing contract

Creation routing — what sends a turn and what writes GitHub

Create PR and Create draft PR send B2 to the active agent. Create PR directly and Create draft directly call B1 immediately. Create PR manually opens GitHub's compare/new-PR page on the configured remote's repository (fork workflows: git.remote may name upstream, not origin) but does not submit it. Separately, "commit and push all changes" only commits and pushes Git; it is not a request to create a PR. A compare URL printed by GitHub is a suggestion, not an existing PR, so the island remains in create mode until sync discovers a real PR number.

Part G — Audit · gaps, edge cases, and things not implemented yet

G Findings

What's missing, inconsistent, or fragile

Ordered roughly by impact. planned = anticipated in code/spec but unbuilt · edge = real scenario that misbehaves · polish = wording / consistency.

planned

G-01 · Five of six [prompts] keys are declared but dead

apps/desktop/src/engine/settings/schema.ts:161-170 defines code_review, create_pr, fix_errors, rename_branch, resolve_merge_conflicts alongside general — mapped to the Review / Create-PR / Fix-errors / Rename-branch / Resolve-conflicts buttons. No [SYS-INSTR: action-*] template exists, no assembler consumes them, and the Actions tab renders only the General preferences field. A user who hand-writes [prompts] create_pr in settings.toml gets silence: the B2 brief and C1–C3 prompts stay hardcoded and non-customizable.

planned

G-02 · The "ONE home for hardcoded agent text" contract has drifted

templates.ts claims every hardcoded agent-facing string lives there, and its deferral note says the Create-PR scaffolding "goes HERE" once built — but the button shipped with its prose in pr-instructions.ts, and further agent prose lives in pr-action-prompts.ts, replay.ts, agent-attachments.ts, agent-chat.tsx (imports), and the adapters (E2/E3). Tracked as hazard P-H2; wording contracts are pinned by pr-instructions.test.ts / pr-action-prompts.test.ts, so consolidation must move the tests too.

edge

G-03 · Mechanism-A orientation can be compacted away

For Claude and Cursor the preamble lives inside the first user message. After a long session compacts/summarizes, the workspace orientation (target branch, don't rename, /add-dir awareness) may vanish, and nothing re-injects it — only a degraded resume re-arms the one-shot. Codex is immune (native developerInstructions). A post-compaction re-inject hook would close this.

edge

G-04 · Plain-folder chats claim a possibly-wrong target branch

Chats without a workspaceId never get ZEROS_TARGET_BRANCH stamped, so the preamble asserts origin/main even for repos whose default is master/trunk or whose remote isn't origin. Also mid-chat settings changes ([prompts] general, target branch) never reach an already-instructed session.

fixed

G-05 · Fixed — failed PR-brief probes remain unknown

askAgentToCreate still uses independent Promise.allSettled reads, but failures now remain nullable. The wire says the count/status/upstream could not be read and asks the agent to inspect the worktree. A confirmed zero emits "Do not create an empty commit"; only a positive confirmed count says "Commit them."

polish

G-06 · Resolve-prompt wording is inconsistent with Update-branch

C1 says "Merge the remote branch (main)…" — it labels the base branch "the remote branch", omits the remote prefix (C3 says origin/main), and drops the final period. With a non-origin git.remote, "the remote branch (main)" is ambiguous about which remote to fetch/merge from. This is a wording revision, not a code bug.

edge

G-07 · /add-dir removals are never announced

Only additions produce the A2 notice. When the user removes a directory the agent keeps believing it has access; its next read fails confusingly. The announcedDirsRef diff is also renderer-memory keyed by chat — on reopen it seeds from the current set, which is correct for the common path but can't retro-announce dirs added while a previous window never sent a turn.

edge

G-08 · Fix-check brief assumes gh auth inside the agent env

D1 tells the agent to run gh pr checks / gh run view --log-failed. Zeros' own PR ops can be brokered through the GitHub App — the agent's shell may have no authenticated gh at all, and gh run view --log-failed without a run id is interactive. The brief has no fallback guidance (e.g., "if gh is unauthenticated, ask the user").

polish

G-09 · Untracked files inflate the brief's "uncommitted changes" count

The count is staged + unstaged + untracked + conflicted; an agent scratch file reads as "1 uncommitted change" in B2's wire text, and the direct path now sweeps that scratch file into its commit without saying which files it took (only how many). A tracked-only count needs a new engine field.

polish

G-10 · Title contract vs sanitizer mismatch (1-word titles pass)

E1 demands 2–3 words, but sanitizeAiTitle only rejects 0 words and clamps >3 — a 1-word reply becomes the tab title. Codex/Cursor also receive the system prompt inside the same user turn (no system channel), so a hostile first message could try to override the contract; the sanitizer limits the blast radius to 3 words but can't stop a misleading title.

planned

G-11 · PR-adjacent agent actions that don't exist yet

No one-click prompts for: fix all failing checks (island only navigates); address all review comments in bulk; update the PR title/description after new commits; rename the branch (reserved in templates); revert a merged PR; reply to / resolve a review thread. Each fits the existing auto-action pattern (short bubble + full wire brief).

fixed

G-12 · Fixed — prompt actions use a synchronous single-flight claim

A ref-shaped claim is acquired before React state or the agent-working signal can lag. It covers prompt, direct, and archive actions; a second same-frame click is rejected, the running icon becomes a spinner, and prompt claims release only when the accepted agent turn settles (success or failure).

fixed

G-13 · Fixed — PR commands shell-quote repository data

The remote, branch, base, and owner/repository now use POSIX single-quote escaping, including embedded apostrophes. The create command also supplies --repo from the configured remote and an explicit --head, preventing gh from silently targeting origin in a multi-remote checkout.

polish

G-14 · No commit-message-convention slot

B2 says "Follow any instructions the user gave you about writing commit messages" — but the only durable place to put such instructions today is the generic [prompts] general. A dedicated commit/PR-description convention slot (fed into the brief itself) would make that sentence actionable.

planned

G-15 · gh is hardcoded into agent prose — blocks future multi-forge support

B2 (gh pr create) and D1 (gh pr checks, gh run view --log-failed) bake the GitHub CLI and "PR" vocabulary into wire text. GitLab or Bitbucket support would require {FORGE_CLI} / {FORGE_CREATE_CMD} / {REVIEW_NOUN} placeholders in templates.ts — "merge request" vs "pull request" must flow into both UI copy and agent prompts.

spec drift

G-16 · The specced user-supplied PR title/description pass-through was dropped

The original specification defined conditional ## PR Title / ## PR Description blocks ("Use it exactly as-is") and a gh pr create --base … --title … --body … command. The shipped brief has no slot for a user-provided title/description — the agent always writes its own. Either re-add the slots or update the spec doc.

polish

G-17 · ZEROS_PERMISSION_MODE is emitted but consumed by nothing

model-catalog.ts:878 stamps it into chat env as a durable record, and the relay scrubber singles it out as dangerous — but no adapter reads it (live sessions use setMode). Harmless today; misleading to the next reader and a stale-posture risk if an env-consuming agent is ever added.

fixed

G-18 · Fixed — PR-island catalog matches direct-action behavior

pr-status-island-state-catalog.html now labels Push / Pull / Ready-for-review / Continue as direct in both the case narratives and its F3 reference table, matching the 2026-07-19 implementation.

fixed

G-19 · Fixed — retained Changes and Review mounted competing islands

Each retained tab previously owned a PrStatusIsland with local live state. The module cache was shared, but a tab's older local snapshot took precedence after the other tab refreshed, producing combinations such as Diverged in Changes and Ready to merge in Review. the workbench now owns one row above both bodies, so the component and status identity do not change on the tab hop.

fixed

G-20 · Fixed — Review's merge CTA bypassed higher-priority blockers

The Review header used only GitHub's coarse conflict fields, so it could offer Squash & merge while the island showed uncommitted/ahead/diverged, pending or failed checks, behind-base, blocked, or checking. Its duplicate CTA now consumes the exact island kind and is enabled only for ready-to-merge; draft readiness is likewise enabled only for draft.

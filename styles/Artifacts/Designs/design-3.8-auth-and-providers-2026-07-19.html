§3.8 Auth & providers · Design catalog · 2026-07-19

Four rows, two touch the UI — an honest sign-in dot and one-click cloud hosting

§3.8 is small but load-bearing: it's how a user knows they're signed in, how the app reacts when a login drops, and where they choose where Claude actually runs. Two of the four rows are done or engine-only; the other two touch pixels — this catalog gives each a before / after on the real Zeros tokens, plus exactly what to implement. Verified against the §3.8 table + the current code (Providers lives at Settings → Agents → Agent providers; the 2026-07-15 IA proposes regrouping it under "Personal — this Mac").

A dot you can trust, a host you can pick Auth state is truthful the instant it changes, and any cloud back-end is one click — never a blocklisted env var hand-edited in TOML.

The dot never lies

Auth state is truthful the moment it changes. Expiry already grays the connected dot in seconds and re-auth greens it (shipped self-heal, §2.3). Signing out mid-chat should gray it immediately — not wait for the next message to fail.

Sign-in comes to you

When a login drops, a sign-in affordance appears in place — a banner above the composer, not a raw red "agent error" inferred from error text. Your pending message sends the instant you're back.

Bring your own cloud, one click

Anthropic, custom gateway, Amazon Bedrock and Google Vertex become first-class hosting modes in the Providers panel. Zeros writes the CLI env for you — the reserved vars stop being something you edit by hand.

Row 4 🎨 UI work P2 🟡 Partial → first-class

First-class Bedrock / Vertex hosting — pick where Claude runs, no TOML

Today the Providers panel offers exactly one bring-your-own route: a custom gateway base_url + API key. Running Claude on your own AWS or GCP account isn't one click — CLAUDE_CODE_USE_BEDROCK / CLAUDE_CODE_USE_VERTEX live only on the credential-redirect blocklist (env-names.ts:102-131) — a repo-[env] security backstop, not a user-facing option — so a power user hand-edits settings.toml. After: a "Route Claude via" selector adds Amazon Bedrock and Google Vertex AI next to Anthropic + the existing gateway; picking one reveals its region / credential fields, and Zeros writes the right env for the CLI.

Row 3 🔍 UI-verify + surface P2 ❌ Missing

Immediate sign-in on auth drop — noticed at once, not on the next failure

Sign out of Claude in another terminal mid-chat and today the connected dot stays green — the loss goes unnoticed until your next message fails. Only then does a text heuristic (AUTH_RX) classify it as auth-required, surfaced as a "SIGN IN REQUIRED" footer pill and a toast that sends you off to Settings → Agent providers. After: the engine consumes a first-class SessionEnd / SDKAuthStatusMessage, so the dot grays the instant auth drops and an in-place sign-in banner docks above the composer — no failed send, no detour. Sign-in opens the Terminal claude /login flow; your pending message sends the moment you're back.

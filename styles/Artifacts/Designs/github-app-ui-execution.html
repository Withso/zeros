One active method, without hidden fallbacks.

A complete before / after and interaction contract for GitHub authentication: three explicit choices, transactional setup, truthful health, every repair state, a restrained toast policy, and a cloud-workspace design held for the future cloud release.

One picker · three real methods Selection and health stay separate; inactive credentials remain saved.

Exactly one active method

The radio selection is durable and restored on first paint. Choosing an unconfigured method starts setup; it becomes active only after verification succeeds.

Selection is not connection health

Offline, rate-limited, SSO-blocked, or awaiting approval never causes a silent method swap and never destroys a usable credential.

Cloud stays design-only for now

The future flow remains documented here, but no cloud authentication UI ships before Cloud Workspaces itself.

Part A — Replace the current implicit connection card

A1 Before After

From one opaque token slot to an explicit three-row picker

Today the settings card reports one connection and hides whether it came from gh, a pasted token, or device flow. The new surface defaults to gh CLI auth, makes the choice durable and visible, and never renders an empty “no method selected” state. The App row is simply GitHub App; it has no product prefix or promotional badge.

Canonical home: Settings → Integrations → GitHub. The same chooser is deep-linked from PR, push, publish, and cloud creation.

Part C — New setup states and just-in-time entry points

C1 New

Each method gets a complete setup path with no dead end

Setup stays inline in Settings. Browser work has a visible waiting state and cancel path; token validation names missing capabilities; CLI absence gets an install link rather than a guessed error.

Automatic token refresh remains silent. Only user action, required repair, or a durable failure gets UI.

gh CLI auth

Use the local CLI session without copying its token into a settings field.

1
Detect locallyInstalled, unavailable, or probe failed are separate states.
2
Sign in if neededRun gh auth login opens the same inline terminal used by Claude and Codex.
3
Verify the accountThe terminal closes on success and the selected row resolves to the username.

GitHub App

Browser authorization and repository installation are treated as two real outcomes.

1
Open GitHubThe previous method stays active while the browser is open.
2
Wait, cancel, or time outA 10-minute attempt can be cancelled and cannot overwrite a later choice.
3
Install or await ownerConnected, no repositories, and approval pending are distinct.

Part D — Future reference, retained until Cloud Workspaces ships

D1 Future cloud Do not implement yet

Fine-grained PAT: repository-scoped, expiring, and explicitly consented

Keep this flow in the artifact as the future product reference. When Cloud Workspaces ships, a Personal Access Token can be supported with a fine-grained token, access to the selected repository, an expiry, and explicit per-workspace consent. None of this belongs in the current product implementation.

Design review only. Implement this section with the Cloud Workspaces release, not with the local GitHub authentication picker.

Part E — Every failure has a named state and a next action

E1 Audit coverage

The UI classifier: never turn an API status into a logout by guesswork

The selected row remains selected through every recoverable state. Only a confirmed 401 marks the credential invalid. A 403, 404, offline probe, or backend failure is classified and repaired without deleting credentials or switching methods.

Part F — Sparse bottom-right toast policy

F1 New

Toast only meaningful outcomes and user-triggered action errors

Connection success and credential removal use the shared toast component. A blocked Create PR, push, publish, or future cloud action reports its error there too. Durable health and repair states stay inline in Settings, but the same event is never duplicated in both places. Use Preview to see every specimen at the bottom right.

No toast for Refresh, method selection, opening GitHub, copying, cancellation, background probes, rate limits, or offline state.

Part G — UI implementation handoff

G1 Build contract

What changes, what is new, and the behavior each surface owns

This is the UI execution list for implementation. It deliberately separates product UI from engine/backend prerequisites so the picker cannot look complete while push, agent Git, or cloud transport still bypass the selected credential.

Surface Status Implementation Acceptance
Current GitHub card Replace Remove the implicit connected/disconnected branches, single token field, device-code block, and disconnected-only Refresh. No hidden fallback or fabricated “CLI not found” copy remains.
Three-method radio group After gh CLI auth · GitHub App · Personal Access Token. gh CLI auth owns the default selection. One tab stop for the group; arrows move and select; an empty selection is impossible.
Per-row setup body New Run gh auth login opens the shared inline terminal; App browser wait and PAT validation render inside their row. Cancel or failure leaves the previous selection and credentials unchanged.
Per-row health New Identity, repository access, expiry, SSO, permission, approval, rate-limit, suspended, and offline states. Refresh retains the last exact-key snapshot. Healthy rows place it at the far right of the detail line; repair states keep it at the top.
Overflow actions New Switch account, configure repositories, stop using, disconnect, or remove as relevant. Popover focus/escape behavior passes the real-browser UI smoke test.
Disconnect GitHub App dialog New Itemized consequences; Cancel owns default focus. The installation is not silently removed on GitHub. Explicit confirmation; no ambiguous “Sign out” that immediately re-adopts gh.
Remove PAT New No modal. Remove immediately and show an Undo toast. Undo restores the encrypted slot without exposing the value.
JIT auth prompt New No inline banner above a composer. A blocked PR, push, publish, clone, or future cloud action uses one bottom-right toast with a Settings action. Draft/action state survives the round trip and resumes after success.
Cloud PAT consent Future Retain in this artifact; implement only with Cloud Workspaces. Show repository, owner, expiry, storage/transport disclosure, and per-workspace checkbox. Fine-grained PAT succeeds; classic, expired, unapproved, SSO-blocked, or wrong-repo tokens get exact repair.
Toast layer New Shared bottom-right component for connection success, removal/disconnection, and blocked user actions only. Durable repair remains inline. No duplicate inline + toast event, no raw API text, and no Refresh/background noise.
Persist semantic selection Store the selected method independently from its health and restore it synchronously. Inactive credentials live in separate encrypted slots.
One credential path The selected method must drive API calls, clone/fetch/push, PR creation, agent-run git, and any gh command.
Classify before mutating A confirmed 401 can invalidate. Rate limits, SSO, permission, repository scope, approval, suspension, and offline never clear a credential.
Transactionally connect Attempt IDs and compare-and-set prevent a late browser or device-flow result from overwriting a newer user choice.
Retain server state Probe by host + method + identity. Keep the last confirmed same-key result while revalidating; “unknown” is never rendered as zero or missing.
Test the owner boundaries Cover App → PAT → App, PAT → gh → PAT, reload, stale persistence, cancel, concurrent probe, 401/403/404, and cloud workspace isolation.
Research basis. The cloud PAT decision in this artifact intentionally narrows the broader-token risk: fine-grained only, repository checked, expiry required, explicit consent, and no token in a remote URL. GitHub organization policy can still require approval or block PAT access entirely, so those are first-class UI outcomes.

§3.6 Models, effort & budget · Design catalog

Six rows, five builds, one reopened — every model/effort/budget gap, before → after

§3.6 is greenfield: nothing in it has shipped yet. This catalog gives each row its user story, the exact surface it touches (composer pills, turn footer, system-notice rows, Settings → Models), and a before / after mockup on the real Zeros tokens. The interaction decisions include no reasoning-token readout anywhere, R2/R3 render as tool calls, and R1 re-examined (Grok 4.5's ladder is reopenable).

Honest endings, bounded spend A turn always says how it ended, never silently truncates, and can never outrun its budget.

Every ending is named

Token cap, budget, blocking limit, fallback, user stop — each gets its own footer pill and notice row, reusing the existing status-pill language. A truncated answer never masquerades as a finished one.

The turn survives the failure

Overload no longer kills the turn: the model falls back and the transcript says so inline. Budget hits stop the turn cleanly with a one-click way to continue.

No new surfaces, sharper existing ones

Everything lands on surfaces users already know: the effort pill's cycle, the turn footer, the EventRow notice, the "…" menu, and Settings → Models. Zero new panels.

Part B — Cursor effort · re-examined 2026-07-13 (Grok 4.5)

R1 Re-examined 2026-07-13 · your question

Cursor effort — hidden by design, but Grok 4.5 is reopenable

You're right to push on this. Cursor is the one family without the effort pill because the SDK exposes no per-request effort/reasoning parameter (unlike Claude's fastMode or Codex's serviceTier): reasoning depth can only change by swapping the model id (applyCursorReasoning → <base>-thinking-high / -fast). Today the catalog pins effortLevels: [] and agentSupportsEffort("cursor") === false is locked by tests. But Grok 4.5 genuinely has a low/medium/high ladder — the ids grok-4.5-low|medium|high exist (verified against cursor-agent models) and the swap machinery is already built and tested. So a Grok effort pill is reopenable via id-swap — with one catch (right).

Answer: possible for Grok 4.5, not Composer 2.5. Not a per-request knob — an id-swap, exactly like the Fast pill already does. A true effort param is still "revisit only if the Cursor SDK grows one."

The catch: the curated id is grok-4.5-xhigh (top tier baked in). That -xhigh suffix trips applyCursorReasoning's "already encodes reasoning" guard, so it returns the id unchanged — Low/Med/High picks would be silently ignored (locked by model-passing.test.ts:135).
The path (two catalog edits, no new UI): (a) set effortLevels: ["low","medium","high"] on the Grok entry — that alone flips the EffortPill on; and (b) change the curated base grok-4.5-xhigh → level-free grok-4.5 (+ alias, + relax the locking tests). Then the pill swaps to grok-4.5-thinking-{low|medium|high} live.
The trade-off: the pill renames the model underneath the user per level rather than tuning a knob — which is why it was hidden. But the Fast pill already does exactly this id-swap, so a Grok effort pill would be consistent with shipped behavior. Composer 2.5 has no such ladder — it stays genuinely effort-less.

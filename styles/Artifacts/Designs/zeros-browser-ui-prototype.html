Provider-native browser use, made visible inside Zeros.

This PR connects Codex to OpenAI’s official bundled Browser plugin and native app-server IAB protocol, enables Claude’s official Agent SDK Chrome integration, and leaves Cursor unavailable because its SDK has no native browser contract. Zeros adds the conversation-owned live tab, inline PermissionCard, settings, cursor, Stop control, and exact-page handoff—without exposing a Zeros browser MCP to any agent.

Shipped implementation map

The live interaction is bound to Zeros-owned identities and the canonical security boundary.

1Permission routed to chat

The existing PermissionCard replaced the global browser dialog. Trusted workspace/conversation attribution, exact-chat queues, and fail-closed teardown are included.

2Same live view attached

Narrow attach, bounds-update, and detach/repark IPC moves the Zeros WebContentsView. It never exposes a generic WebContents handle.

3Auto-open is conversation-safe

Exact conversation-keyed state adds and activates the Browser tab on first open. Redirects and background chats update without stealing focus.

4Live work is visible and stoppable

Favicons, cursor motion, scroll, the cyan working tint, trusted action capsule, input lock, and Stop all follow host-owned state.

5Browser use settings shipped

Browser use sits directly under Agents, opens with Codex first, and keeps one global product policy across Codex, Claude, Cursor, and later adapters.

6Lifecycle and transcript hardened

Codex keeps its native titled node_repl.js calls instead of emitting click/snapshot spam, Stop invalidates current work, and a kept or interrupted page is handed back without reloading it.

What was retained from the earlier prototype?

Auto-open planning, Browser-tab attachment, activity labels, and an injected agent pointer were retained. Task/Codex-owned identity assumptions, provider switching, raw CDP, and popup confirmation were deliberately excluded.

/Native contracts

Provider tools stay provider-native

Zeros standardizes ownership, policy, UI, and handoff—not the tool vocabulary presented to every model.

No fallback MCP

“Canonical contract” in plain language

The canonical Zeros seam is now host-side: acquire one browser lease for a workspace conversation, register the native provider session, route visible state and approvals to that conversation, and release it on deletion. Codex still speaks OpenAI’s IAB protocol and shows node_repl.js; Claude still speaks Anthropic’s Chrome protocol. There is deliberately no common agent-facing zeros_browser tool set.

Current and future adapters

Each adapter opts in only through an official provider contract.

CodexNative

OpenAI’s browser@openai-bundled plugin, official node_repl MCP dependency, and app-server IAB session metadata.

ClaudeNative

Official Claude Agent SDK --chrome integration. Chrome / Edge and the Claude extension own its tabs and approvals.

CursorUnavailable

No browser tools are injected because the current Cursor SDK has no official browser-use contract.

Future agentOfficial API required

May opt into Zeros hosting only after its own SDK or app server exposes a native browser contract.

Host-side lifecycle contract

These are product operations, never model-visible MCP tools.

acquire Zeros internal

Create or reuse one opaque, memory-only browser lease for a durable workspace and conversation owner.

register Codex internal

Bind the exact app-server thread id to that lease so authenticated IAB requests cannot cross conversations.

attach / detach UI internal

Move the same Electron WebContentsView between its parking host and the visible workbench rectangle.

handoff lifecycle

Remove agent control, cursor, debugger, and interaction lock while preserving the exact live page for the user.

release Zeros internal

Destroy ephemeral page data when the conversation is deleted, Browser use is disabled, or the trusted app surface closes.

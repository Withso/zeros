Changes tab · Review tab · PR status row · State catalog

Every state the PR status island can show

The PR status row is the first row of both the Changes tab and the Review tab — one stable 40px home for PR creation and PR status. Without a PR it holds the branch → target picker and Create PR; with a PR it becomes the status island: one derived state at a time, with the button that resolves it. This catalog is the full inventory — every state, when it appears, and what its actions do.

14 island states + 3 pre-PR states First match wins, top to bottom. Fix the tree, then the PR.

One state at a time

The island never stacks messages. A priority decision over all inputs picks a single label with 0–2 action buttons — the one thing to do next. Local blockers always outrank GitHub's opinion.

Three data sources, applied atomically

gitStatus (local truth: conflicts, uncommitted, ahead/behind) + ghPrGet (GitHub: draft/merged/closed, mergeable state) + ghPrChecks (CI). Results land as one settled batch, so mixed-generation flashes can't render.

Actions resolve the state

Most buttons send a prompt to the active chat — the agent does the git work. Only Merge (squash via gh), Archive (parks the workspace) and Show checks (opens Review) act directly.

How it works
  • Branch name is plain fg2 text that truncates on narrow rows; the arrow reads as "merges into". No "Target branch" label — the geometry says it.
  • The dropdown opens a searchable picker of remote branches only (a PR merges on GitHub, so the base must exist there). Picking a new base rebases the branch onto it.
  • Create PR drops a PR-creation brief into the active chat — the agent reviews the diff, commits, pushes, and runs gh pr create. Once prNumber lands, this row becomes the island.

Part B — Island bootstrap · loading & the honest fallback

B1 Ships today

First load — chip + "Loading...", no guessed state

The true first load of a workspace's PR: no settled data yet, so the island derives nothing. Just the #N ↗ chip and a quiet "Loading..." label. A guessed intermediate ("PR open" → "Ready to merge" a beat later) reads as status churn — a plain "Loading..." says it honestly (no spinner, 2026-07-19 spec).

A last-known cache re-renders the previous status instantly on tab switches — this spinner shows only once per workspace + PR.

B2 Ships today Fallback

"PR open" — GitHub metadata genuinely unavailable

The fetch round settled, the local tree is clean, but ghPrGet returned nothing — offline, or gh unauthenticated. "PR open" is the honest floor: a PR exists, and that's all we can truthfully claim. No actions.

Part C — Local blockers · fix the working tree first

C1 Ships today Warning tone

Merge conflicts

The highest-priority non-terminal state — it wins over everything except merged/closed. Appears when the local tree has conflicted paths (or a conflict state like a paused rebase), or when GitHub reports mergeable_state: dirty (D-branch, same render). Resolve prompts the agent to rebase onto the base, fix every conflict, verify build + tests, then push.

kind: merge-conflicts · tone warning · Resolve (prompt)
Two triggers, one state: local conflicts, or GitHub dirty.
View PR Merge conflicts Resolve
Design note
  • Every open-PR state renders on the shared brown surface (--pr-status-surface) — an --fg1 label, a --brown-primary chip, and a filled primary action (the white primary button in Shade, a solid --brown-fg in Light) so its icon stays legible in both themes. The tone is still warning in the state machine; whether conflicts should read hotter than brown (a dedicated red surface) is an open review question.
C2 Ships today

Uncommitted changes

Staged + unstaged + untracked + conflicted counts sum above zero. The PR can't reflect work that isn't committed, so this outranks everything below it. Commit & Push prompts the agent to commit with a conventional message and push (setting the upstream if the branch has none).

kind: uncommitted · tone neutral · Commit & Push (prompt)
View PR Uncommitted changes Commit & Push
C3 Ships today

Ahead by N commits

Everything is committed, but local commits haven't been pushed — the PR on GitHub is stale. The label counts them ("Ahead by 1 commit" / "Ahead by 3 commits"). Push prompts the agent to push the branch so the PR catches up.

kind: ahead · tone neutral · Push (prompt)
ahead is null (skipped) when the branch has no upstream.

Behind by N commits

The upstream has commits this local branch doesn't — e.g. the agent pushed from another session, or a teammate pushed to the same branch. Pull prompts the agent to pull (rebase preferred), resolve anything, and push the result.

D2 Ships today

N checks pending… — CI running, nothing failed

CI is still running and no check has failed yet. There is nothing to do but wait, so the row shows no buttons — just the live count from ghPrChecks, singular/plural aware ("1 check pending…" / "5 checks pending…"). It updates on the shared git-refresh signal.

kind: checks-pending · tone neutral · 0 actions
View PR 5 checks pending…
D3 Ships today Danger tone

Unable to merge — a check failed

At least one check failed, or GitHub reports unstable. A known failure wins over "pending": checks run concurrently, so one commonly fails while others are still in flight — a calm "5 checks pending…" would hide the failure the user needs to see. Show checks opens the Review tab, where the failing run's Checks sub-tab and its "Add to chat" fix-it brief are one click away.

kind: unable-to-merge · tone danger · Show checks (navigation)
Never gated by the agent-working rule — it's pure navigation.
View PR 1/6 checks failed Show checks
Design note
  • Like C1, tone danger renders on the shared brown surface (--pr-status-surface) rather than a dedicated red one — no red label. The tone hook exists in CARD_TONE/LABEL_TONE if review decides failures should read red.
D4 Ships today

Require branch to be up to date (behind base)

GitHub's mergeable_state: behind — the base moved on and the repo requires branches to be current before merging. Update branch prompts the agent to rebase onto the latest base, resolve anything, run relevant tests, and push.

kind: behind-base · tone neutral · Update branch (prompt)

D5 Ships today

Blocked from merging

GitHub's mergeable_state: blocked — branch protection is unsatisfied: a required review is missing, a required check hasn't reported, or a merge queue gate. Nothing in this app can resolve it, so the row shows no buttons.

kind: blocked · tone neutral · 0 actions
View PR Blocked from merging
D6 Ships today Transient

Checking mergeability…

The default floor: checks are green (or absent) but GitHub hasn't computed mergeable_state yet — typically the seconds right after a push — or returned a state we don't recognise. Resolves itself on the next refresh. Stability rule (2026-07-19): when a definitive state was already showing, a transient "unknown" from GitHub is MASKED by it for up to 30s while the island re-probes quickly — this row renders only on a true first load, right after a direct action, or when GitHub is genuinely stuck.

kind: checking · tone neutral · 0 actions
has_hooks is treated as clean, so hook-enabled repos can't get stuck here.

Part E — Terminal states · ready, merged & closed

E1 Ships today Success tone

Ready to merge — the green row

Tree clean, everything pushed, checks green, GitHub says clean (or has_hooks) and isMergeable isn't false. The whole row turns --green-bg with a --green-fg label — the strongest "you're done, ship it" signal in the tab. Merge is the island's only green filled button; it calls gh pr merge --squash directly and toasts the result.

kind: ready-to-merge · tone success · Merge (direct, squash)
Gated while the agent is working — see F1.
View PR Ready to merge Merge
E2 Ships today Merged tone

Merged — the violet row

The PR merged (state or mergedAt). Terminal: nothing local matters any more, so this wins over every other state. The row turns --violet-bg/--violet-fg and offers two exits: Continue (dashed) prompts the agent to summarise what shipped and plan the next task in this workspace; Archive (filled) parks the workspace — with Undo.

kind: merged · tone merged · Continue (prompt) + Archive (direct)
View PR Merged Continue Archive
How it works
  • Archive stops any running agent turn, repoints the view (so the open chat isn't stranded on a deleted folder), and offers Undo in a toast.
  • The only state with two buttons — "keep going here" vs "this workspace is done".
E3 Ships today Closed tone

Closed — without merging

The PR was closed on GitHub without merging. Also terminal, but deliberately not celebratory: the row turns --red-bg with a --red-fg label and chip — abandoned, not shipped, so no violet and no Continue. The lone Archive is the white primary button (same as Merged) — it parks the workspace, with Undo.

kind: closed · red surface · Archive (direct, filled)
View PR Closed Archive
Design note
  • Unlike C1/D3 — warning & danger that still render on the shared brown surface — Closed gets its own --red-bg surface: terminal and unambiguous. The View PR chip outline is a new semantic, --pr-status-chip-border-closed — a muted brick red (--red-750 · #7b3021) in Shade that flips to --red-300 on the light salmon surface. Label and chip text are --red-fg in both themes.
  • Archive is the filled white primary button shared with Merged; in Light it stays white with a hairline border instead of the dark inverted fill, so it still reads as a button on the salmon row.

Part F — Cross-cutting behaviour

F1 Ships today Gate

Agent working — mutating actions park until the turn ends

While the workspace's agent has a turn in flight, every prompt action and Merge disable at 50% — a prompt would queue behind the very turn still reshaping the branch, and a merge could ship a half-pushed state. Archive (deliberately stops the agent) and Show checks (pure navigation) stay live. The tooltip explains the gate.

The priority ladder — first match wins

derivePrIslandState walks top to bottom and returns the first hit. The order encodes the workflow: fix your working tree, then look at the PR. Pure data-in / data-out — the whole matrix is unit tested.

Quick reference — every state at a glance

Kind, label, tone, actions, and the exact trigger. Action behaviours: prompt sends a templated brief to the active chat (the agent does the git work), direct calls the engine, nav focuses the Review tab.

Kind Label Tone → render Actions Trigger
merged Merged merged → violet row Continue (direct, new branch) · Archive (direct) PR state merged, or mergedAt set
closed Closed closed → red row Archive (direct, filled) PR closed without merging
merge-conflicts Merge conflicts warning → brown row Resolve (prompt) Local conflicted paths / conflict state, or GitHub dirty
uncommitted Uncommitted changes neutral → brown row Commit & Push (prompt) staged + unstaged + untracked + conflicted > 0
ahead Ahead by N commit(s) neutral → brown row Push (direct) Local commits not on the upstream
behind Behind by N commit(s) neutral → brown row Pull (direct) Upstream commits not local
draft Draft PR open neutral → brown row Ready for review (direct) PR state draft, or mergeable state draft
pr-open PR open neutral → brown row — Fetch settled but GitHub metadata unavailable
unable-to-merge N/M checks failed (or "Unable to merge") danger → brown row Show checks (nav) failed > 0, or mergeable state unstable
checks-pending N check(s) pending… neutral → brown row — pending > 0 and nothing failed
behind-base Require branch to be up to date ( N commits behind ) neutral → brown row Update branch (prompt) Mergeable state behind
blocked Blocked from merging neutral → brown row — Mergeable state blocked (branch protection)

Freshness
  • Refetches on the shared git-refresh signal (turn end / DB write) — not a poll. A failed source keeps its last-known value rather than blanking the row.
  • The View PR ↗ chip is constant across every state and focuses the Review tab; the tab's own header keeps the "Open on GitHub" external link.

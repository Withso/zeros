UI implementation catalog · Current PR · 2026-08-10

Organization management moves to the web; the Mac scopes local work to the selected owner.

This catalog shows only UI and user-visible behavior implemented on the current branch compared with origin/main. It separates functional management surfaces from intentionally disabled future controls, and keeps the signed-in web dashboard distinct from the desktop handoff flow.

Implementation, not proposal Web: organization administration. Mac: organization selection + workspace scope.

The browser owns administration

Create, identity, members, invitations, roles, teams, billing status, and deletion now live at app.zeros.build.

The Mac owns working context

The Home rail selects Personal or an organization; workspace cards, tabs, pending rows, archives, and counts follow that owner.

Capability is not provisioning

Cloud eligibility is visible, but cloud workspace creation, extra teams, and billing management remain intentionally unavailable.

Part C — explicit boundaries in the implemented UI

B Not shipped in this PR

Visible capability scaffolding does not imply the feature is available

These are the important limits to preserve when reviewing or presenting the PR.

Eligibility only

Cloud workspaces

Organizations can display “Organization eligible,” but there is no cloud create, provision, join, or history UI.

Disabled

Additional teams

The default child team is visible. New team · Coming later is intentionally disabled.

Disabled

Billing management

Plan and member/seat status render. Checkout, invoices, payment methods, and Manage billing do not.

Browser-owned

Desktop administration

The Mac does not duplicate create, rename, member, team, billing, or delete controls; it opens the web dashboard.

Context, not badges

Workspace ownership

Cards and tabs do not gain organization badges. The active switcher context determines which rows exist.

Repositories remain local

Repo list

Repository names stay visible in the rail. Workspace counts and rows—not repositories themselves—are owner-filtered.

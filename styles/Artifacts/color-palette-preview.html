Zeros — Color in Context

The six semantic color families applied to real Zeros UI, rendered on the app canvas (--bg1). This page is about how color is used, not the raw palette — for the token definitions, ramps, and component library see design-system-preview.html.

red — error · −N deletions · deleted green — success · +N additions · in-review · created yellow — warning · modified · in-progress blue — info · links · accents violet — done · merged brown — file paths · warm accents

1 Diff counts & status squares

Standalone counts and icons on the canvas use the vivid --<family>-primary accent.

+985  ✚  new-feature.tsx
+12 −4  •  edited.ts
−58  —  removed.md
✚ created • modified — deleted
tokens: +N --green-primary · −N --red-primary · modified --yellow-primary

2 Kanban statuses

Colored dots for active states; neutral --fg3 for backlog / cancelled (no color = not started / dropped).

Backlog 0 In progress 0 In review 1 Done 0 Cancelled 0
tokens: in-progress --yellow-primary · in-review --green-primary · done --violet-primary · backlog/cancelled --fg3

3 Delete button + icon

The one place a family uses a solid fill: destructive actions fill with --red-secondary (deep red 700), white text. Standalone delete icons use the same token.

solid · white text · bg = --red-secondary
tokens: fill + icon --red-secondary. Inline error text instead uses --red-primary.

4 Tinted callouts fg / bg contrast

Filled notices: surface = --<family>-bg, text + icon = --<family>-fg (never the vivid primary — that would read "all red/green"). No border.

7.9:1 ErrorFailed to write file — permission denied. ✔ used: panel error boxes, git errors, error event rows (~13 sites)
9.3:1 SuccessCursor validated your API key. ✔ used: PR ready-to-merge island, provider ‘validated’ box, PR ‘Open’ badge
6.9:1 Warning3 files have uncommitted changes. ✗ NOT a container today — warning is icon / text only
8.7:1 InfoThis runs in an isolated workspace. ✗ NOT a container today — info is text / links only
6.5:1 MergedPR #12 merged into main. ✔ used: PR ‘merged’ island + badge
tokens: surface --<family>-bg · body --<family>-fg · bold lead label --<family>-primary

5 PR states

Pull-request islands reuse the tinted-surface recipe: green for ready-to-merge, violet for merged.

#12 ↗ Ready to merge
#12 ↗ Merged
tokens: ready --green-bg/--green-fg, action fill --green-primary · merged --violet-bg/--violet-fg

6 Links / info

Inline links and info text use --blue-primary — text only, no container.

Open the documentation or view #12 on GitHub.
tokens: link + info text --blue-primary

Inline file paths (agent output)

Edited apps/desktop/src/renderer/shell/workbench/workbench-pane.tsx and styles/globals.css — clickable chips, brown to stay distinct from blue links.
tokens: file-path chip text --brown-primary on --bg1-highlight

7 Toasts

Toasts stay a neutral card — only the status icon is colored. No tint (this is deliberately different from the tinted callouts above).

✔ Pushed to main.
✕ Couldn’t add this project.
▲ Attachment is too large.

Card = --bg2 + --border2 + --shadow-dropdown; only the leading icon carries the family --<family>-primary.

→ Role → family (quick reference)

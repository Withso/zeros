# Format: directories, frames and pages

The files a Design directory holds, how frames and pages are registered, and the HTML and CSS frames may use.

## Directory layout

```
<Repo name> - Design/
  meta/design.toml          registration: format, version 3, stable directory ID (engine-owned)
  meta/canvas.json          pages, frames, geometry, foundation metadata, style sources, themes, fonts
  rules.md                  generated rules, then project guidance appended below them
  tokens.css                Design-only tokens (the theme editor's Manual source)
  components/<name>.html    older reusable components (read, never added)
  assets/                   images used by frames
  <page-folder>/<frame>.html
```

- **Never create, edit, move or delete `meta/design.toml`.** Registration, rename and removal go through Zeros (Settings or the Design tab). Preserve the directory ID in any repair.
- `rules.md` is regenerated by Zeros; text appended after the generated block survives upgrades. Add project rules at the end only.
- Legacy layouts (root `design.toml`/`canvas.json`, flat HTML) stay readable; explicit authoring upgrades them.
- Commit the whole folder together. `.zeros/` is private local state and stays ignored.

## Frames

One registered HTML file is one frame. Only files listed in `meta/canvas.json` `frames` appear on the canvas; any other HTML is just source.

To create a frame:

1. Write `<page.folder>/<name>.html` (one folder segment, inside that page's folder).
2. Add a record under a new stable ID in `frames`, then append the ID to that page's `frames` array. Save the HTML first.

```json
{
  "version": 2,
  "pages": [{ "id": "page_home", "title": "Home", "folder": "home", "frames": ["home_default"] }],
  "frames": {
    "home_default": { "kind": "html", "source": "home/default.html", "title": "Home — Default",
                      "x": 0, "y": 0, "width": 1440, "height": 900 }
  }
}
```

```html
<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8" />
    <title>Home — Default</title>
    <link rel="stylesheet" href="../tokens.css" />
    <style>.card { padding: var(--space-4); border-radius: var(--radius-md); }</style>
  </head>
  <body>
    <main class="card">
      <h1>Welcome</h1>
    </main>
  </body>
</html>
```

- **IDs** start with a letter, use letters, digits, `_` or `-`, and are at most 128 characters. Never change an existing directory, page or frame ID. Renaming a file changes only its `source`.
- **Geometry.** `width`/`height` (1–16,384) are the frame's viewport; `x`/`y` stay within ±1,000,000; optional `z` is 0–1,000 within its page.
- **`data-oid`** is optional: the canvas derives selection identities for plain HTML, and visual edits save the IDs they need. Keep existing values when you edit; add stable, unique ones when selection must survive a large restructure. Document plumbing (`html`, `head`, `body`, `meta`, `link`, `title`, `style`, `script`, `template`) never takes one.
- **References** resolve relative to the file that contains them, so frames in page folders link `../tokens.css` and `../assets/…`.
- **Layout.** Prefer normal flow, flex and grid with `gap` and padding for content. Use absolute positioning for intentional overlays and decorative shapes inside a relative container.
- Keep unrelated metadata, unknown fields and other agents' changes. Re-read a file before editing it.

`kind: "text"` frames are canvas text blocks created from the Design tab; author `html` frames.

## Pages

- Add a page by appending `{ "id", "title", "folder", "frames": [] }` to `pages` and creating the folder.
- Folder rules: 1–64 letters, digits, `.`, `_` or `-`; starts with a letter or digit; no trailing dot; unique case-insensitively; never `meta`, `assets` or `components`. A lowercase slug is best. A page titled "Components" therefore needs another folder, such as `components-2` (the folder Zeros page creation chooses for that title).
- Renaming a page changes its title only; the folder never moves. Each frame belongs to exactly one page and its source stays in that page's folder.
- 1–64 pages and at most 1,000 frames per page. A directory has no separate frame limit; a page over 1,000 does not open until frames move to another page.

## Sections, notes and link cards

A page's optional `items` list holds canvas annotations people place with the Section, Note and Link card tools. They are canvas chrome, not design: they never appear inside a frame, in Layers, or in any capture, preview or export.

```json
"items": [
  { "id": "sec_onboarding", "kind": "section", "x": 0, "y": -60, "width": 480, "text": "Onboarding" },
  { "id": "note_copy", "kind": "note", "x": 1500, "y": 0, "width": 240, "height": 160, "text": "Check the empty state\nand the error copy" },
  { "id": "link_brief", "kind": "link", "x": 1500, "y": 200, "width": 280, "target": "docs/brief.md", "title": "Brief" }
]
```

- **IDs** follow the frame ID rules and are unique across every frame and item in the directory.
- **Geometry.** `x`/`y` within ±1,000,000; `width` 1–16,384. A note also needs `height` (1–16,384); a section's and a link card's heights come from their text.
- **Text.** A section title is one line of 1–120 Unicode code points. A note holds up to 2,000 code points and keeps its line breaks. A link card's optional `title` is one line of up to 120 code points and defaults to the file name; clearing a custom title restores that fallback.
- **Link targets** are workspace-relative file paths of up to 512 characters: no leading `/`, `\`, `~`, URL or scheme, no empty, `.` or `..` segment, no control characters, and no private files (`.git`, `.zeros`, `.env*`, keys, databases and the like). A card opens its file in Files; a missing file shows as "File not found". An internal symlink to a regular file works, but a symlink whose resolved target leaves the workspace is missing. Nothing is ever fetched.
- At most 256 items and 256 KiB of item text per page. An invalid item is skipped without reserving its id against a later valid item; canvas edits and deletes act on the entry that is drawn and keep the skipped one exactly as written. Skipped items are reported by `design validate` (`canvas-item-invalid`, `canvas-item-link-unsafe`, and `canvas-item-link-missing` for a file that is gone), all as warnings; the canvas stays readable. An unknown `kind` is kept as written and not drawn. Valid items past the cap still reserve their ids, and the canvas says how many more items are not shown.
- Keep items people placed; add or edit them only when asked.

## Components

- Markup used three or more times is a component. Make it a **main frame**: an ordinary frame in a page folder, registered with a `component` field (below), and place it elsewhere as `<zd-<name> data-oid="…">`. Never add `components/<name>.html`.
- Keep the main's `data-oid` values stable: an instance's inner layers are named by them, and its overrides point at them.
- Keep scripts, event handlers and external URLs out of a main, as in any frame.
- **Older `components/<name>.html` files** stay valid and render as before: `data-zid` names their layers, `<slot>` takes instance children and `<slot data-zd-attr="label">` an escaped attribute value, and their references resolve from the Design root. Leave them as they are unless asked; a person turns one into a main with Move main to canvas on a selected instance, one undo step.

### Components with options

A frame becomes a component when its file declares options and its record in `meta/canvas.json` registers a name. People adjust options in the Style panel; you create and change them. There is no JavaScript: Zeros evaluates the template below itself, and nothing else runs.

Register the frame with a `component` field on its record. The name is the tag other frames use:

```json
"chat_composer": { "kind": "html", "source": "chat/composer.html", "title": "Chat composer", "component": "chat-composer",
                   "x": 0, "y": 0, "width": 1120, "height": 240 }
```

Declare options in `<head>`, one element per line, each closed with its end tag. Only the first `<template data-zd-options>` in `<head>` is read; one in `<body>` or a second one is ignored and `design validate` warns:

```html
<template data-zd-options>
  <zd-option name="width" type="number" label="Width" default="1120" min="640" max="1440" step="8" unit="px"></zd-option>
  <zd-option name="attachments" type="number" label="Attachments" default="2" min="0" max="4" step="1"></zd-option>
  <zd-option name="mode" type="choice" label="Mode" choices="ask plan" default="ask"></zd-option>
  <zd-option name="toolbar" type="boolean" label="Toolbar" default="true"></zd-option>
  <zd-option name="accent" type="color" label="Accent" default="var(--blue-primary)"></zd-option>
  <zd-option name="send-radius" type="number" label="Corner radius" group="Send button" default="8" min="0" max="16" unit="px"></zd-option>
  <zd-option name="send-label" type="text" label="Label" group="Send button" default="Send"></zd-option>
  <zd-option name="motion" type="easing" label="Easing" default="spring(0.2) 150ms"></zd-option>
  <zd-derive name="gutter" value="width >= 1200 ? 24 : 16" unit="px"></zd-derive>
  <zd-variant name="compact" width="800" mode="plan"></zd-variant>
</template>
```

- **Kinds.** `slot` (below), `number` (`min`, `max`, `step`, `unit` of px, %, rem, em, ch, vw, vh, fr, deg, ms or s; it is a slider only with both `min` and `max`), `boolean`, `choice` (2–16 lowercase values in `choices`; labels come from the values, or `choice-labels="Ask|Plan"`), `color` (a colour or `var(--token)`), `text`, `easing` (a keyword, `cubic-bezier()`, `steps()` or `spring(bounce)`, then a duration). `group` folds consecutive options under one heading. `label` defaults to the name.
- **Names.** Lowercase letters, digits and single hyphens, at most 32 characters. Not `name`, an HTML attribute an element keeps (`class`, `style`, `id`, `hidden`, `title` and the like), anything starting `data-`, `aria-`, `on` or `zd-`, or a function name.
- **Variants** are named sets of values (`default` is taken: it is the declared defaults). **Derived values** are expressions over options, worked out in order.
- **Values in CSS.** Number, colour, easing and numeric derived options are custom properties: `var(--zd-width)`, `var(--zd-accent)`, `var(--zd-motion-easing)` and `var(--zd-motion-duration)`, `var(--zd-gutter)`. These names count as known tokens in lint. Text, choices and booleans reach the markup only through the template.
- **Template.** In a declaring file, `{{ expression }}` fills text and attribute values (escaped), `data-zd-if="expression"` keeps an element only when true, and `data-zd-for="item in list"` repeats it (`range(n)` or `["a", "b"]`, up to 256 times, nested 3 deep). A `<template data-zd-if>` or `<template data-zd-for>` wraps without adding an element. Holes do not work in `<style>`, `<script>`, comments, the options block, or in `style`, `href`, `src`, `srcset`, `action`, `formaction`, `poster`, `srcdoc`, `data`, `xlink:href`, `ping`, `background`, `cite`, `manifest`, `codebase`, `id`, `data-oid`, `data-zid`, `data-zd-*`, `on*` attributes or a `<meta>` `content`. Write a literal `{{` as `{{ "{{" }}`.
- **Expressions.** Numbers, `"text"`, `true`/`false`, lists, names, `( )`, `!`, `-`, `* / %`, `+ -` (`+` joins text), `< <= > >=`, `== !=`, `&& ||`, and `a ? b : c`; functions `range`, `min`, `max`, `clamp`, `round`, `floor`, `ceil`, `len`. Types never convert: `"2" + 1` is text, `mode + 1 > 2` is an error. Put spaces around a minus (`width - 1`), since names may contain hyphens.

Place an instance with its values as attributes. A missing attribute takes the variant's value, else the default; write `false` explicitly:

```html
<zd-chat-composer data-oid="ws-composer" zd-variant="compact" width="760" toolbar="false"></zd-chat-composer>
```

- **Slots.** Mark a frame in the main `data-zd-slot="body"`; what it holds is the default. That makes it a slot option; declare `<zd-option name="body" type="slot" label="Body"></zd-option>` (never with a `default`) only to give it a label, a group or its place in Options. An instance's children with `slot="body"` replace it; give them their own `data-oid`:

  ```html
  <div class="card-body" data-oid="body" data-zd-slot="body"><p data-oid="placeholder">Empty</p></div>
  <zd-card data-oid="plans" heading="Plans"><p data-oid="plans-copy" slot="body">Pick a plan.</p></zd-card>
  ```

  A bare `<slot>` in the main is the default slot, filled by children with no `slot` attribute.
- The component's linked stylesheets come with it, and its URLs resolve from its own file. Its inner layers carry `data-zd-part` (their `data-oid` in the main, or `data-zid` in a `components/` file).
- **Part overrides.** An instance restyles one of its parts, or hides it with `display: none`, through `zd-style-<part>` on its host, where `<part>` is the part's `data-oid` in the main: `<zd-card data-oid="plans" zd-style-heading="color: var(--fg2)">`. The override wins over the part's own rules and its options; text still changes only through options. Clear the attribute to return to the main.
- Changing an option on an instance changes one attribute; on the main component it changes the `default` (or the variant line it shows). Keep one element per line so each change is one line in Git.
- **Change a component's options** (when a person asks, or Zeros sends "Change the options of …"): ask what to change first. Add, remove, rename or regroup `<zd-option>` lines and their template uses together; keep existing names and values unless asked, since instances in other frames carry them as attributes; keep one element per line; run `design validate` on the component and on frames that place it; capture it before and after; never stage or commit.
- **Fix a component's options** (Zeros sends "Fix the options of …" with the problems): run `design validate`, repair each named declaration, expression or instance value at its line with the smallest change that keeps what the person set, validate again until it reports none, capture the frame to check it renders, and say what changed. Never stage or commit.
- `design validate` reports options, expressions and instance values that do not fit, an instance attribute that names no option of its component (it is ignored, never rewritten), an instance of a component that no longer exists (its main was deleted, renamed or unregistered; it renders nothing; the message says whether the registered file is missing or nothing defines the name; a component that is there but unusable, such as a symbolic link or an oversized file, is reported by its own error with the reason instead), an unregistered frame that declares options, and a name registered twice or also used by `components/<name>.html`. When options cannot apply, the frame keeps its last good render in this session, or shows the component's defaults, or shows nothing in that place when the template fails even with its defaults (a main's own failing template renders an empty body, never its raw `{{ }}` text); its canvas label, and the label of every frame placing it, carries a red mark saying which. A declaration over 160 elements, 72 attributes per element, or attribute values over 2,048 characters still renders, but its Options cannot be shown and `design validate` warns which limit it passed (`component-option-invalid`).

## Assets and media

- Images: `.png`, `.jpg`, `.jpeg`, `.gif`, `.webp`, `.avif` inside the Design directory (keep them in `assets/`), up to 10 MiB each and 12 MiB of images per frame. They are inlined when the frame renders.
- Fonts: an `@font-face` rule in Design CSS (`tokens.css`, a page stylesheet or a frame `<style>`) can use `.woff2`, `.woff`, `.ttf` or `.otf` files inside the Design directory (keep them in `assets/fonts/`, with their license). They are inlined from CSS only and count toward the 12 MiB per-frame budget. Prefer fonts from an imported style source when the application already ships them.
- Inline `<svg>` markup works. SVG files and video do not load.

## Supported and not supported

| Works | Does not work |
| --- | --- |
| HTML and CSS, flex, grid, custom properties | `<script>`, inline event handlers, JavaScript, JSX or TSX |
| CSS `@keyframes` animations and transitions (represent states visually) | `<iframe>`, `<object>`, `<embed>`, `<base>` |
| Raster images and font files from the Design directory or a style source; Google Fonts, downloaded once and embedded | Network requests from frames: remote images, stylesheets or APIs |
| Inline SVG | SVG or video files; `javascript:` and non-raster `data:` URLs |
| Manual tokens, themes and declared style sources: CSS, Sass, the application's Tailwind utilities, build outputs | CSS `@import` in Design CSS; Tailwind `@config` and plugins other than typography, forms and tailwindcss-animate |
| Components (`<zd-name>`) | Live application components (planned as separate Code layers) |

Represent controls as visual states (default, hover, pressed, focus, disabled) in separate frames or labelled rows. Generate source with shell, Node or Python if useful; the output must still be HTML and CSS.

## Limits

| Resource | Limit |
| --- | --- |
| Pages per directory / frames per page | 64 / 1,000 (no directory-wide frame limit) |
| Text file (HTML, CSS, metadata) | 2 MiB each |
| One frame and the files it links (tokens, page CSS, components) | 1,024 files, 16 MiB; there is no directory-wide size budget |
| Stylesheets linked by one frame | 128 |
| Rendered frame after inlining | 15 MiB, including 12 MiB of images |
| Style sources | 16 per directory; 32 MiB per file, 64 MiB and 1,024 files per compiled source, 16 MiB of fonts per source. Frames receive only the rules, faces and characters they use. |
| Live frames on the canvas | 12 (others show a still image) |
| Capture | 2048 × 2048 PNG, 20-second deadline, one at a time |

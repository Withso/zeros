## Fixture compute retirement and storage debt

A bounded canary cannot wait for a provider's six-hour signed-upload fence
on each hourly run. Keep physical deletion and record purge under their
existing positive proof; give fixture cleanup a separate authenticated
compute-retired/storage-pending outcome. Retain every generation and disk
reservation, the original delete time and the unchanged operation key.

Mirror the standalone control-plane schema exactly and test parity. A durable
deleting inventory row can still report the old compute allocation; the fresh
retirement response is compute proof and the complete inventory is disk/coverage
proof. Test that sequence, stale proof across inventory reads, contradictory
physical flags, foreign/live work and the backlog boundaries before widening
admission. Recheck after a slow Computer build as well as before it.

When moving local investigations into Actions, explicit authenticated receipt
selection is the only cleanup allowlist. A signed compact handoff confers no
build, runtime, wake or credential authority. Preserve consumed handoff identity
after resources disappear; replays must not resurrect a completed local run.
Test the real Actions checkpoint chain and legacy artifact semantics, with
storage debt visible independently of lifecycle success and every first failure.

Runner liveness and disk audits use PID files with `kill -0`, exact process-name
matches or `/proc/<pid>/cwd`. Never list full command lines or environments:
supervisor sessions can carry credentials there. Environment-path diagnosis
extracts only the required path tokens. The audit for this change used PID/cwd
metadata only; no command-line or environment census was needed.

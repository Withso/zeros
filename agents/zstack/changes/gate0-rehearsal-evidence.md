## Rehearsal evidence follows the real protocol and measured interval

The native completion frame omits chatId, and a retired native host can expose
null executionId in a later snapshot. Bind completion to the exact durable
command/turn/execution receipt and boot scope, retain transcript identity and
prove contiguous replay. Do not invent fields in a fake protocol response.
Every pre-disconnect row must survive; allow its active payload to finish while
requiring immutable user-prefix bytes. A missing tool row cannot count as a
complete transcript just because the final assistant marker is present.
The Gate 0 concrete-adapter regressions cover both real shapes and foreign
identity refusals. The generated Python task executes under an injected clock
in its test, including exclusive-output duplicate refusal.

Admission does not prove an agent is working, and readiness can follow several
failed setup claims. Observe the task heartbeat before closing the device;
require a successful one-claim setup for first-try readiness. A real thirty-
minute device gap has no hidden token refresh or CP poll. Verify the recorded
auth validity first, then reconnect and prove the original execution. The
zstack-verify live evidence rules apply to these measured intervals; desktop UI
and CP-outage claims stay separate. Tests cover short auth/timers, retrying
setup, incomplete replay and first-failure preservation.

Manual rehearsals share fixture concurrency and cleanup receipts with hourly
runs, while exact job names keep their results out of hourly admission. A
signed report preserves every failed attempt and the selected time window;
raw socket counters and admission retries have separate denominators. Missing
measurements remain unavailable. Protocol, profile, metric and output-race
tests plus the three accompanying eval fragments encode these checks. Keep
these lessons in this fragment until the integrator folds the pack; concurrent
lanes must not append to a shared playbook anchor.

A randomly generated public key exposed an argv edge: base64url can start with
`-`, which Node's strict parser treats as an option. Normalize that one validated
value into the known `--public-key=` form, and retain a deterministic dash-key
regression. Real protocol-shaped inputs must not turn randomness into a flake.

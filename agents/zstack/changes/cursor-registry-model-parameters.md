# Account model parameters are startup input

A curated Cursor model was selectable but its execution endpoint rejected the
parameters. Discovery raced native create/resume, while curated effort/Fast
defaults were treated as a complete account-specific schema. The SDK's ID
validator did not fill omitted provider parameters. An explicit empty schema
also inherited guessed fields, and an execution-rejected model reappeared as
selectable after discovery.

Rule for bug-fix: use the complete live default variant for parameterized
registry selections, within the existing discovery budget. Recheck original
account/lifetime after the wait; do not invent fields, swap an explicit registry
selection, or turn a display catalog into eligibility. Execution refusal must
disable the exact account model during refresh. Keep unavailable saved choices
visible with a reason and an action to choose a verified alternative.

Encoded in Cursor model-passing/boot-native-handoff regressions and the real
shared-default-model browser smoke for Local, organization-local and cloud.
Evals: `cursor-registry-model-parameters`, `unavailable-model-recovery-menu`.
The synthetic required-default fixture proves the source race, not which
parameter a particular live provider request lacked.

Browser theme coverage must assert the rendered theme after imports. Setting a
document attribute before the real appearance store loads can silently test
Dark twice; seed the store and retain the rendered-theme regression.

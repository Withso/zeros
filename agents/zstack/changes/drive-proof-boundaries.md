# Drive the supported surface and name its evidence boundary

A Linux development VM is not a Zeros cloud placement. `electron:local` is
macOS-only; browser harnesses import production renderer components but simulate
transport, file writes, PTYs and provider events. Use them for visible behavior,
then leave native engine and live-worker claims explicitly unverified until those
runtimes are exercised. A fixture provider status cannot prove authentication.

Before driving, record the host, owner, placement and expected end state. Use a
fresh browser context for each fixture, assert state and backing readbacks before
capturing, and keep evidence under the checkout's `.context/`. Stop only the
launch you own and wait for its listener to close: a package-manager parent's
exit can precede its child. Preserve any failed cleanup observation when recording
a successful retry.

Evidence: the zstack-drive Linux walkthrough exercises workspace A → B → A,
settled chat disclosure, file saves for three owner/placement combinations,
Accept/Cancel review, and terminal docking for the same three combinations.
Native macOS, actual provider turns and Boat lifecycle are separate follow-ups.

# A saved account is not a healthy selection

Organization Settings could report Connected from a saved selection while the
exact credential had expired. Selecting a fresh native import could conflict,
then show a raw error or publish after the initiating owner/dialog retired.

Rule for bug-fix: consume the strict optional health observation at its existing
network boundary. Bind it to the selected credential and revision, keep absent
metadata unavailable, and never infer readiness from an unselected import or an
in-progress refresh. Reconnect uses the existing fresh native ceremony. Retain a
completed import on selection conflict and use refreshed revisions only after
another explicit Connect; do not retry a write or import automatically. Check
the captured owner epoch and active dialog after every held continuation.

Encoded in the actual Settings form handlers, strict metadata parser, held
native/selection replies and real Dark/Light Settings browser smoke. Local
subscription/status suites remain adjacent. Eval: `cloud-selected-account-health`.

When extending mocks under Vitest, do not return a mock from beforeEach: it can
be interpreted as a cleanup callback. Retain the first invalid fixture run,
correct it and prove the functional red against immutable production source.
New browser scenarios that persist a selected provider need their own browser
storage so an existing default-selection scenario still tests its intended state.

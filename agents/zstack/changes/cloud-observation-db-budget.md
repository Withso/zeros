# Bound cloud observation work by ownership and measured cost

Symptom: a few open chats consumed database capacity through idle context renewal, rapid empty control polls and GitHub reads on every Git broadcast. Exact runtime qualification reads also scanned unrelated historical registry rows. A cloud avatar lookup crossed its repository read policy and lost the closed refusal status.

Cause: observation retained the same recurring work as native execution; Git freshness and remote PR freshness shared one trigger; concurrent authority reads did not share an exact flight; a flattened lateral lookup lost its selective query plan.

Rule: count recurring requests in a one-engine/multiple-chat minute and price them with real transaction timings, including setup/RLS/commit. Restrict renewal to exact native ownership (including preparation and unproved descendants), preserve deadline/revocation checks, and never postpone an existing renewal on unrelated activity. Share overlapping exact requests, charge every admitted waiter, join cleanup, and repeat authority checks after I/O. Bound remote observations independently of local state; one cached result must not start a reconciliation per edit. Prove query scans with historical registry volume, rather than inferring a latency gain from fewer statements.

Encoded in the boot runtime/factory, GitHub proxy and real-PG boundary tests, runtime scan EXPLAIN regression, cloud PR observation/effect controls, and the eval cases added with this fragment. Local Personal and organization-local paths retain their original behavior. Memory evidence must distinguish bounded live payloads from process RSS and identify the measured platform; heap collection alone does not prove RSS release.

1How the three surfaces fit together

Auth0 is the one source of identity. Railway is the source of product data (orgs / teams / secrets). They never talk directly — the Auth0-signed token is the courier. Your role in organization_members, not the token, decides what you can do.

1. Web login → Auth0 → provider consent (once) → 30-day KV session cookie. Browser never touches Railway.   2. Handoff → "Launch Zeros" mints a single-use PKCE ticket; the Mac redeems it proving a verifier that never leaves the Mac, storing its own tokens in the keychain.   3. Provisioning → the app's first /v1/me call makes the backend verify the token and create user + org + team in one transaction (the only moment a Railway row is born).   4. Sync → every 15 min it pulls org secrets into the engine; sign-out couriers an empty context.

2Scary findings that turned out to be false

Three automated audits ran; I hand-checked every "critical" against the code. Two of the scariest don't hold — recording them so we don't waste a PR fixing non-problems.

ClaimRatedVerdict
Handoff ticket stolen from URL → token theftCriticalFalse — proper PKCE. Redeem needs sha256(verifier)==challenge; the verifier is born on the Mac and never travels. A stolen ticket alone is useless.
Org secrets linger in memory after sign-outCriticalFalse — org-sync.ts:77 couriers an empty secrets map whenever not authenticated.
Open redirect via return paramsMedFalse — safeReturn() allows only https + *.zeros.build.
Logout GET is a dangerous CSRFHighLow — worst case is a forced sign-out to a sanitized URL. Real but minor.

3Real findings, prioritized

Tier 1 — quick, high value (do now)

1
Add security headers to app.zeros.build Medium
Verified live: only referrer-policy is set. Missing HSTS, CSP, X-Frame-Options, X-Content-Type-Options — enables clickjacking + first-visit downgrade.
Fix: a website/web-app/public/_headers file · ~15 min
2
Enforce Postgres RLS for real High (mitigated)
Verified live: the app connects as the postgres superuser, which bypasses every RLS policy. The row-level rules are decorative today — authorization is 100% app-layer (which is the real lock, and correct), but the backstop is off.
Fix: non-owner zeros_app role + FORCE ROW LEVEL SECURITY · ~1–2 hrs, own PR
3
Rate-limit the un-capped backend mutations Medium
Create-org / create-team / role-change / write-secret have no limit — a logged-in user can spam them (audit-log flood). The three riskiest routes already are capped.
Fix: global rateLimit("global", 100, 60_000) on /v1/* · ~30 min

Tier 2 — worth doing, more design

4
Revalidate web sessions against Auth0 Medium
A KV session is a 30-day cache never rechecked with Auth0 — a deleted/blocked user keeps a working browser session until TTL. (The Mac app is fine; its refresh re-proves liveness.)
Fix: store issuedAt, liveness-check on reads >24h old · ~2 hrs
5
Backpressure on just-in-time signups Medium
ensureUser() mints user+org+team for any new Auth0 sub on every request — many accounts could mass-provision rows. Auth0 anti-abuse is the first line; no backend ceiling exists.
Fix: per-hour signup counter, or lean on Auth0 + document · ~2 hrs
6
Postgres pool hardening Low
No statement_timeout (a hung query pins a pool slot) and no enforced sslmode.
Fix: statement_timeout: 30_000 + assert TLS · ~20 min

Tier 3 — accepted risk / document only

  • Refresh token plaintext in KV — inherent to KV as the server trust boundary; encrypting adds marginal value. Low
  • SameSite=Lax cookie — fine for modern browsers; Strict would break the Auth0 return navigation. Leave as is.
  • Shared browser+desktop refresh-token family — Auth0 design tradeoff, already mitigated by the single-flight refresh mutex + shared-secrets sync.
  • Vault master-key rotation — not implemented (would orphan secrets). Write a runbook before it's ever needed.

4Suggested PR sequencing

PR-A (small, this branch): _headers + backend global rate limit + statement_timeout. Low-risk, high-value, no schema change.

PR-B (own branch): zeros_app role + FORCE ROW LEVEL SECURITY + green RLS tests. Needs a Railway credential change — deploy carefully.

PR-C (own branch): web session revalidation + JIT signup ceiling.

Docs: vault key-rotation runbook + Tier-3 accepted risks in the backend README.
